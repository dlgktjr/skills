# session-wrap — progress.md 를 지금 상태로 다시 쓴다

progress.md 는 일지가 아니라 **현재 상태판**이다. 다음 세션의 나(또는 다른 사람)가
이 파일 하나만 읽고 이어서 일할 수 있어야 한다. 그래서 덧붙이지 않고 매번 전체를 다시 쓴다.

## 절차

1. **기존 progress.md 를 읽는다.** 없으면 새로 만든다.
2. **이번 세션에서 실제로 일어난 일을 모은다** — 대화 기록, 바뀐 파일(`git status` · `git diff --stat`),
   이번 세션에 돌린 명령과 그 결과, `PLAN.md` 가 있으면 노드별 상태. 기억에 의존하지 않고 확인할 수 있는 것을 근거로 쓴다.
3. **기존 내용과 합친다** (덧붙이기가 아니라 다시 정리):
   - 기존 `아직 못한 일` · `다음에 할 일` 중 이번에 끝낸 것 → `한 일` 로 옮긴다.
   - 이번에 새로 생긴 미완료 → `아직 못한 일` 에 넣는다.
   - 더 이상 맞지 않는 내용(뒤집힌 결정, 해결된 문제, 바뀐 경로)은 고치거나 지운다.
   - 같은 내용이 두 번 나오지 않게 한다.
4. **파일 전체를 아래 형식으로 덮어쓴다.**
5. **사람에게 바뀐 점을 3줄 이내로 알린다** — 새로 끝난 것 · 새로 생긴 할 일 · 지운 것.

## 형식

```markdown
# Progress

마지막 갱신: YYYY-MM-DD HH:MM · 브랜치 `<branch>` · 커밋 `<short-sha>`   (git 저장소가 아니면 날짜만)

## 지금 상태
한두 문장. 무엇이 동작하고 무엇이 막혀 있는가.

## 한 일
- (최근 것이 위) YYYY-MM-DD · 무엇을 했나 — 관련 파일/커밋

## 확인한 결과
- `명령` → 결과 (exit 0 · 테스트 12/12 통과 · 화면 확인 등) · YYYY-MM-DD
- 확인하지 않은 것은 여기 쓰지 않는다

## 아직 못한 일
- 무엇 — 막힌 이유 / 남은 부분

## 다음에 할 일
1. 가장 먼저 할 일 — 시작할 파일 · 명령까지 구체적으로
2. …

## 결정과 이유 (바뀌지 않는 한 유지)
- 결정 — 이유
```

## 규칙

- **덧붙이지 않는다.** 세션마다 블록을 쌓지 않는다. 섹션 구조는 늘 위 형식 하나다.
- **확인한 결과에는 근거가 있는 것만 쓴다.** 돌리지 않은 테스트를 "통과"로 쓰지 않는다.
  실패했으면 실패라고 쓴다. 건너뛴 확인은 `아직 못한 일` 로 보낸다.
- **지어내지 않는다.** 이번 세션에서 알 수 없는 것은 쓰지 않거나 `(확인 필요)` 를 붙인다.
- **날짜는 절대 날짜로 쓴다.** "오늘" · "어제" 를 쓰지 않는다.
- **길이를 관리한다.** `한 일` 이 15줄을 넘으면 오래된 것부터 한 줄 요약으로 묶는다
  (예: `2026-10-20 ~ 10-25 · 초기 구조와 테스트 환경 구성`). 파일은 한 화면에서 훑을 수 있어야 한다.
- **비밀정보를 쓰지 않는다.** 키 · 토큰 · 개인정보 · `.env` 내용.
- progress.md 를 커밋할지는 사람에게 묻는다. 묻지 않고 커밋하지 않는다.
